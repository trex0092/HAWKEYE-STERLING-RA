# Model Card — Sanctions / Watchlist Name Matcher

*Card date: 2 Jul 2026 · Revised: 28 Jul 2026 (accuracy-hardening programme — shared transliteration data, phonetic fold layer, one-way threshold config, benchmark floors) · Type: **deterministic fuzzy matcher** (no ML, no LLM) · `sanctions-match.mjs`, `screen.py:screen_name`*

| Field | Detail |
|---|---|
| **Purpose** | Decide whether a customer, UBO, director or counterparty name matches a designated party on the consolidated sanctions / watchlists — the operative FATF R.6/TFS control. |
| **Business owner** | MLRO. |
| **Technical owner** | Compliance Engineering. |
| **Inputs** | Subject name (+ jurisdiction/ID when available) and the consolidated lists: OFAC SDN **primary + a.k.a. aliases (alt.csv)**/non-SDN, UN, EU, UK OFSI, the maintained UAE EOCN Local Terrorist List. Names are Unicode-normalised (incl. the Turkish dotless-ı fold in both engines); transliteration variants generated **in both engines** from the single shared data file **`data/translit-groups.json`** (89 disjoint groups, 267 members — `ai.name_variants` in Python, `nameVariants` in JS; both loaders fail loud on a missing/malformed file, schema-guarded by `test/translit-data.test.mjs`). |
| **Outputs** | Per-subject: top score (0–100), band, hit list with matched entry and score, including token-**subset** (patronymic-chain) hits and **phonetic-only** hits — a pair whose per-token romanization-robust phonetic keys agree exactly (or form the strict subset shape) flags at its real conservative score with confidence **`WEAK (phonetic-only)`**, never confirmed-looking (`phonetic_key`/`phoneticKey`, identical spec both engines; `MATCH_PHONETIC` ∈ 1\|shadow\|0). A **MANUAL REVIEW** marker (score-0, `unscreenable`/`review`) for names that cannot be auto-screened — too short, no distinctive tokens, or carrying non-Latin-script letters the Latin fold loses (`_lost_script_letters` / `lostScriptLetters`). Material-match threshold 85/100 (`MATCH_THRESHOLD`, Python) = 0.85 fraction (`SCREEN_MATCH_THRESHOLD`, JS) — both env-tunable **one-way** (lowering is plain config; raising above the champion default is rejected loudly without the explicit `…ALLOW_RAISE=1` override), and both engines carry the log-only **shadow challenger** band (`SHADOW_THRESHOLD` / `SCREEN_SHADOW_THRESHOLD` — evidence for the champion/challenger decision log, never a hit or case). |
| **Knowledge / training source** | None trained — token-sort/fuzzy similarity (RapidFuzz on the Python side) over the live lists; no historical model. |
| **Prompt strategy** | N/A. |
| **Limitations** | Fuzzy matching trades false positives for recall; very short or non-Latin-only names cannot be auto-scored → routed to MANUAL REVIEW rather than passed; list freshness depends on the Sanctions Watch pipeline. The former "every-token ≥2 edits off clears by design" residual ("Muhamet Huseinn" ≈ 69) is **closed by the phonetic fold layer** (28 Jul 2026) — its negative-test pin is FLIPPED to a required WEAK phonetic-only catch, with `MATCH_PHONETIC=0` as the kill-switch regression guard. **Remaining documented residuals** (benchmark ids, 3 per engine, pinned by the floors' fn cap): triple-token drift where one token pair is phonetically ambiguous (r110, farag/faraj — Egyptian ج romanizes as both g and j; both engines); Turkish legal-form abbreviation vs the full boilerplate chain (r081/r085 — Python's `min(full, core)` structural guard; the JS engine catches these); a JS-only prefix-cluster gap (r120 achraf/ashraf — the Python engine catches it). Leading-vowel drift (omar/umar) is deliberately NOT phonetic — it lives in the transliteration groups; single-significant-token names never phonetic-match. Since 5 Aug 2026 the JS engine scores with the same decisive `min(full, core)` as Python (the earlier collapse-to-core `max()` scorer rated any two corporates sharing one distinctive token 100/critical — the n086-n090 hard-negative class) and keeps the recall that collapse used to provide through ported short-entry and near-exact-core gates; subset/phonetic-only evidence bands review/medium with mechanism + confidence labels, never a confirmed-looking match. Both engines hold a 1.0 unnoted hard-negative floor. |
| **Known risks** | **False negative** (missed designation) is the critical failure — mitigated by transliteration variants, the conservative threshold, MANUAL REVIEW routing, and the **refuse-to-clear** guard (no list loaded ⇒ run bails, never a false all-clear). False positives mitigated by MLRO four-eyes review. Risk register R-04 (matching quality), R-05 (fairness). |
| **Bias assessment** | **Formally measured.** `test/bias_eval.py` (CI-enforced) holds labelled Latin / Arabic / Turkish / Cyrillic / CJK / Phonetic equivalence sets and asserts ≥90% recall per group with a ≤10% cross-script gap (raised from 70%/30% on 28 Jul 2026; currently 100% in every group, gap 0%, both backends) — a fairness failure here is a discriminatory *false-negative*, so it is treated as a compliance defect. See [`../aims/bias-fairness-testing.md`](../aims/bias-fairness-testing.md). |
| **Human oversight** | Detection is automatic; the freeze / decline / report action is always an MLRO decision with dual attestation (UAE Federal Decree-Law 10/2025 Art.16/18; FATF R.26). |
| **Monitoring** | `test/sanctions-match.test.mjs`, `test/sanctions-match-fuzz.test.mjs`, `test/engine_test.py` recall-gap check every push/PR; daily Sanctions Screen run log + coverage-degradation alarms. |
| **Performance metrics** | **Labelled accuracy benchmark, CI-floored per backend** ([`../governance/screening-accuracy-benchmark.md`](../governance/screening-accuracy-benchmark.md)): sanctions recall **97.5%** (118/121; floor 95% with a 3-miss cap) vs the frozen pre-hardening baseline of 57.0% (py) / 62.0% (js); hard-negative clear 100% unnoted (py) / 96.5% (js, documented). Cross-script recall parity within bound (CI); standing matches recorded once, new/changed matches always alert. Benchmark-relative — outcome-based validation runs through the backtesting protocol. |
| **Retirement criteria** | Replace if the firm adopts a commercial screening engine (e.g. World-Check); the card and the egress allowlist would be revised and re-validated. |
